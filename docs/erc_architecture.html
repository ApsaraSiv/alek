How the library-robot's ROS 2 nodes fit together

TIAGo Pro finds a shelf column, reads a book off it, and carries it to the collection bin. Seven nodes across two packages divide that job into perception, navigation, manipulation, and one orchestrator that calls into the other three — plus MoveIt and Gazebo underneath, which none of the team's own nodes replace.

Roles

Perception
erc_perception + book_detector (erc_solution)

Four independent, single-purpose nodes, each subscribed to the same head camera feed, each publishing one fact and nothing else. None of them plan or drive — they only report what the camera currently sees.

  • pub/erc/shelf_column_identification
  • pub/erc/shelf_column_horizontal_error
  • pub/erc/shelf_row_identification
  • pub/erc/target_book_point
  • pub/erc/bin_identification
book_detector is the odd one out: it also reads the depth image, and its 3D point goes straight to manipulation rather than through the state machine, because it exists to correct for exactly how far off-target navigation actually parked.
Navigation
erc_solution · navigation_node

One node, two blocking services, both driving the same holonomic mecanum base. It does not search for the column marker itself — that loop lives in the state machine, which only calls approach_shelf once it has already centred visually.

  • srvapproach_shelf — square up, drive to LiDAR standoff
  • srvnavigate_to_bin — waypoint drive to the start zone
  • sub/odom, /scan_front_raw, /scan_rear_raw
  • sub/joint_states — wheel-stall detection
Both drives share one stall-recovery routine: if commanded wheels read near-zero velocity for too long, reverse briefly and resume rather than push against whatever it's stuck on.
Manipulation
erc_solution · manipulation_node

Right-arm pick-and-place, planned through MoveIt's low-level MoveGroup action rather than moveit_py. It corrects two things navigation can't: how far off-centre the base parked, and how high the target row sits.

  • srvgrasp_book(row) — hover, approach, close, verify, retreat
  • srvplace_in_bin — fixed pose, since navigation already parked at a known standoff
  • pub/cmd_vel — lateral strafe before planning
  • pub/torso_controller — lift for rows above baseline reach
A successful MoveGroup plan only means the pose was reached. The real grasp check is /contacts showing a gripper_right_* / book_* collision, re-checked after retreat, not just at the moment the gripper closes.

Two things that surprise people reading this graph cold

Perception can skip the orchestrator
target_book_point goes directly from book_detector to manipulation_node. state_machine_node never routes it — it just waits for grasp_book() to return.
The orchestrator drives the robot too
During SEEK_COLUMN, state_machine_node publishes /cmd_vel and head-tilt commands itself — it only hands control to navigation_node once perception has already confirmed centring.
